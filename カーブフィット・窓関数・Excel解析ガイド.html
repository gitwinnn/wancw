第1部｜カーブフィット法ほうとは何か

先にひとことで言い切ります。

測定した点々（ガタガタしたデータ）に、物理的に正しいはずの「なめらかな数式の線」を当てはめて、その数式から本当の値（固有振動数こゆうしんどうすう・減衰げんすいなど）を逆算する作業のことです。

🌊 たとえ話：バネと重りの実験

バネに重りをぶら下げて手を離すと、揺れはだんだん小さくなります。1秒後10cm、2秒後6cm……という具合です。理論上はなめらかに減っていくはずですが、実測すると誤差（ノイズ）が混ざって点がガタつきます。そこで「一番よく合う、なめらかな理論の線」を計算で探すのがカーブフィットです。

オレンジの点＝実測、水色の線＝計算で当てはめた「本当はこの形のはず」という数式

🎯 あなたの測定（FRF）での意味

ハンマーで叩いて作る周波数応答おうとう関数（FRF）の「山」も、物理法則から決まった数式の形になるはずです。カーブフィットで山の形に数式を当てはめれば、ノイズに惑わされず正確に固有振動数と損失係数を取り出せます。

⚠️ なぜ半値幅法だけでは足りないのか

半値幅法は「定規で山の幅を測るだけ」の一番シンプルなカーブフィットです。山が1つだけ、きれいに孤立している時は十分な精度が出ます。しかし、あなたのブレーキパッドは穴で対称性が崩れて縮退しゅくたい双子ふたごモード（2つの山が重なって1つに見える）が出やすく、この場合は定規（半値幅法）では答えが大きくズレます。

💡 原理のイメージ：バネ・重り系の揺れ方は物理法則から「必ずこの形の数式になる」と決まっています。その数式の中の“つまみ”（固有振動数・減衰・大きさ）を、実測データに一番合うようコンピュータで自動調整するのがカーブフィットの正体です。

第2部｜窓関数が「要る・要らない」の見分け方

結論から言うと、判定基準はただ1つです。

記録した1コマ（フレーム）の中で、たたいた後の揺れの波形が「終わりまでにほぼゼロまで減衰しているか」だけを見ます。

🔎 なぜ「終端の段差」がダメなのか

FFTは切り取った1コマが無限にループすると仮定します。終わりと始まりに段差（不連続点）があると、そこにニセの高周波成分（漏れ＝リーケージ）が発生し、山の形がなまって損失係数（減衰）を過大評価してしまいます。だから「終端がゼロになっているか」が唯一のチェックポイントです。

🛠 あなたの RION SA-01A4 での確認手順

  1. 解析モードをFFT解析にし、ハンマリング測定を1回行う。
  2. 画面の「全時間データ」または時間波形表示で、応答（振動）チャンネルの波形を目視。
  3. フレーム（記録時間の1コマ）の終端付近で、波の振幅がノイズの床（フロア）に埋もれているかを確認する。
  4. 埋もれていれば → 窓＝「無し」（方形窓）でOK。何も足さなくて良い、一番正確。
  5. まだ波が見えていれば → 「フォース・指数」窓が必要（基準チャンネル＝ハンマー側にフォース窓、応答側に指数窓）。

🟢 補足：ハンマー（力）信号側は常に「フォース窓」でOK

ハンマーで叩いた力の信号は、当たった瞬間以降は物理的に本当にゼロです（叩いていないから）。なのでフォース窓（打撃の前後だけを残し、あとは強制的にゼロにする窓）をかけても、データを歪めることにはなりません。これは応答側の指数窓（本当は減衰していないのに人工的に減衰させる）とは性質が違うので、区別して考えてください。 🟢検証済み

📐 判定を数値で裏付ける（目安の計算式）

軽い減衰の系（バネ・重り系）の揺れは、指数関数的に小さくなります。目標の減衰量（例：-60dB＝1000分の1）まで減衰するのにかかる時間 t は、次の式で見積もれます。

t = ln(1/r) / (π・fn・η)　　※ r＝目標振幅比（例：-60dB なら r=0.001）

dB表記で言うなら：

t = (dB × ln(10) / 20) / (π・fn・η)

第3部｜窓が要らない場合の「測定時間（ブロック長）」の決め方

窓を使わずに済ませたい時は、「たたいた後の揺れが記録時間内にちゃんとゼロまで収まる」ように、記録時間 T（＝ブロック長 N 点 ÷ サンプリング周波数 fs）を決めます。

🔗 うれしい副産物：分解能もついでに良くなる

記録時間 T を長くすると、周波数分解能 Δf（＝ 1/T、正確には fs/N）も同時に細かくなります。つまり「窓なしにするために記録を長くする」ことは、「双子モードを見分けやすくする」こととも一致します。デメリットとぶつからない、珍しい“両取り”ができる場面です。

Δf = fs / N　　（N＝FFTの解析点数、fs＝サンプリング周波数）
T = N / fs　　（この T が、揺れが収まるのに必要な時間より長ければ窓は不要）

🧮 手順（手取り足取り）

  1. 第2部の式で「窓なしに必要な最低記録時間 t」を計算する（例：0.0785秒）。
  2. RIONの「解析周波数」レンジを決める（例：20kHzレンジ → fs=20000×2.56=51200Hz）。
  3. 解析点数 N（64〜32768）を、T=N/fs が t より少し余裕を持って大きくなるように選ぶ。
  4. 選んだ N と fs から Δf を計算し、モード同士の間隔（例：40Hz差の双子）に対して十分細かいか確認する（目安：Δf はモード間隔の1/5以下が望ましい）。
  5. 「ウインド」設定を「無し」にする。

第4部｜ハンマリング×Excelで「疑似ポリリファレンス」カーブフィットを組む

🔴 最初に正直な前提をお伝えします

本物の「MIMO＋ポリリファレンス（PolyMAX等）」は、複数の加振点（参照点）のデータを、行列の多項式固有値問題という高度な数値計算で同時に解く手法です。この“行列の多項式を固有値分解する”部分は、Excelの標準機能（関数だけ）では原理的に組めません（対応する組み込み関数が無いため）。 🔴要確認・原理的な限界

そこでこのガイドでは、数学的な考え方は本物のポリリファレンス法と同じ「有理多項式カーブフィット（RFP法）」を、Excelの標準機能（MMULT・MINVERSE・Solver）だけで組める形にした実装を提供します。まず1つの加振点（ハンマー1点）のデータで双子モードをきれいに分離できることを、実際に数値検証した上でご案内します。複数加振点への拡張方法は4-8節で説明します。

4-1｜全体の考え方（噛み砕いた版）

FRF（周波数応答関数）H(ω) を、「分子の多項式 ÷ 分母の多項式」という形の数式でまるごと表現します。

H(ω) = [ b0 + b1(jω) + b2(jω)² + b3(jω)³ ] / [ a0 + a1(jω) + a2(jω)² + a3(jω)³ + (jω)⁴ ]

分母を4次にするのがポイントです。分母の式を「＝0」と置いた方程式（特性方程式）の根（解）が、ちょうど2つのモード（双子）の固有振動数と減衰に対応します。4次方程式は根が4つ出て、複素共役のペアが2組＝モードが2つ、というわけです。

b（分子）と a（分母、最高次の係数は1に固定）は未知数ですが、実はこの式は見かけによらず「1次方程式（線形）」に変形できます。これが数値的に解ける理由です。

4-2｜準備するデータ

  • 調べたい双子モードの周波数帯を含むFRFデータ（RIONまたはPSVからエクスポート）：周波数 f [Hz]、実部 Re(H)、虚部 Im(H) の3列。
  • 点数の目安：20〜80点程度（帯域の中に2つの山がきちんと収まっていること）。

4-3｜Excelシート構成（列ごとの計算式）

まず基準周波数（帯域の中心くらいでOK）を決めて、周波数を「正規化（normalization：単位のない扱いやすい数字に変換すること）」します。これをやらないと数値が大きすぎたり小さすぎたりして、Excelの計算誤差が無視できないほど大きくなることを数値実験で確認しています（生の周波数のまま計算すると、双子の分離に失敗します）。 🟢検証済み（Python二重計算で確認）

4-5｜分母の方程式を解いて「2つのモード」に分ける（Excel Solver）

Q30:Q37 で求めた a0,a1,a2,a3（a4は1固定）を使い、分母の4次方程式を「2つの2次方程式の掛け算」に分解します。

s⁴ + a3・s³ + a2・s² + a1・s + a0 = (s² + p1・s + q1)(s² + p2・s + q2)

展開して係数を比べると、4つの式が出てきます。

p1+p2 = a3　／　q1+q2+p1p2 = a2　／　p1q2+p2q1 = a1　／　q1q2 = a0

4-8｜本物の「複数参照（多点加振）」への拡張方法

ハンマーで複数の場所を順番に叩けば（例：角①と角②の2箇所、応答は同じ1点で固定）、相反性（そうはんせい／reciprocity：Hij=Hjiという物理法則）を使って、実質的に2つの参照点を持つデータセットが作れます。これは実務でも使われる、シェーカーを2台用意しなくても済む現実的なMIMO化のやり方です。

Excel上での拡張は次のようになります。

  • 分母（a0〜a3）の列は2つの参照データで共通のまま使う。
  • 分子（b0〜b3）は参照点ごとに別々に用意する（参照2用にb0'〜b3'の列を追加）。
  • 行列の列数が 4(参照1のb) + 4(参照2のb) + 4(共通のa) = 12列に増える。行数は参照1と参照2のデータを縦に積み増しした分（点数×2×2）になる。
  • 4-4・4-5の手順はそのまま（MMULT・MINVERSE・Solverの範囲を広げるだけ）で成立します。

正直な限界：参照点が3つ以上になったり、モードが3つ以上重なる複雑なケースになると、Excelの行列サイズ・Solverの収束の手間が急激に増え、実務としては非効率になります。その規模になったら、Python（scipy／numpyは既にお使いのLinux Mint環境で動きます）に切り替える方が速く確実です。🟡推定（規模の目安、要はお使いになってからの感触次第）

第5部｜注意点・よくあるミス 総まとめ

  • 正規化を忘れる：周波数をそのままHz単位で計算に使うと、数値が大きすぎて誤差で答えがズレる。必ず基準周波数で割って正規化すること。
  • 帯域の選び方が広すぎる／狭すぎる：2つの山がちゃんと収まる範囲で、余計な他のモードを含めない帯域を選ぶ。
  • Solverの初期値が山からかけ離れている：グラフを見て「だいたいこの辺」という初期値を必ず入れる。ゼロや適当な値からだと収束しないことがある。
  • ハンマー信号にフォース窓をかけ忘れる：ハンマー側は常にフォース窓（または窓無しでも打撃前後を十分ゼロ区間にする）にする。
  • 応答が終端で減衰しきっていないのに窓無しにする：第2部・第3部の手順で必ず確認してから決める。
  • 2度打ち・叩き損じたデータを混ぜる：カーブフィットの前に、時間波形で2度打ちが無いか目視チェック。
